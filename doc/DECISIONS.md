## 代码核对依据

当前代码核对结果：

- 后端基于若依 `3.9.2`，已有用户、全局角色、菜单权限、字典、系统配置、全局操作日志和通用上传资源。
- 当前本地分支已提交 PM-0002 项目和项目成员实体、创建/列表/详情接口、前端列表与详情页面、增量 SQL 和针对权限、成员隔离、唯一性及事务的测试；后端提交 `4c512b1`，前端提交 `1bd8c1d`。
- PM-0002 增量 SQL 尚未应用到 MySQL；本机开发配置指向 `localhost:3306`，当前无可用本机 MySQL 服务。
- 当前已存在需求基础记录、需求首版本、需求负责人和任务基础创建接口及对应首版本/负责人/分类关系；任务列表、编辑版本、附件和 Agent 业务接口仍未实现。
- 注册接口存在，初始化配置 `sys.account.registerUser` 默认开启；管理员仍可通过该配置关闭注册。
- `/profile/**` 当前允许匿名访问，不满足私有项目附件要求。
- 现有全局操作日志不能直接替代项目级日志和 AI 调用记录。

这些是代码事实，不是已完成的产品功能。

## 待确认问题

### DEC-Q001 权限范围

已确认：普通需求和任务编辑由独立权限控制，并通过全局角色分配；具备对应权限的项目成员可编辑当前项目内同类记录，不按创建者或负责人硬编码。

### DEC-Q002 角色权限映射

各全局角色具体对应哪些项目菜单、按钮和数据操作权限？项目管理员资格是否单独配置按钮权限？

### DEC-Q003 字典初始值

第一期默认提供哪些任务分类、需求状态和任务状态？

### DEC-Q004 字典存量行为

字典值改名、停用后，已引用该值的当前记录是否允许编辑？当前记录显示旧名称还是新名称？

### DEC-Q005 附件策略

已确认：每个需求版本最多 10 个附件，单文件不超过 20 MB、版本合计不超过 100 MB；支持 PDF、DOC、DOCX、XLS、XLSX、PNG、JPG、JPEG；项目成员可访问，图片/PDF 可预览，Office 文件下载；清单变化生成新版本，旧版本附件永久保留且不可改写，不提供公开直链。

### DEC-Q007 任务更新版本

已确认：任务详情提供“按最新需求版本更新”操作；确认后编辑标题和说明，生成新任务内容版本并关联确认时的最新需求版本，旧版本保留并记录 `TASK_VERSION_UPDATE` 项目日志。状态、分类和负责人不在本轮内容版本表单内，继续遵守各自独立字段规则。

### DEC-Q008 Agent 服务

已确认：Agent 服务采用可配置的服务端适配层，供应商、模型、密钥、是否外发和费用限制均不固定为单一实现，由服务端配置管理。

### DEC-Q009 Agent 文件解析

已确认：文件格式、大小、扫描件/OCR、Excel 多工作表和解析能力均由服务端配置管理；解析输入必须遵守需求附件允许范围和项目访问边界。

### DEC-Q010 Agent 失败和重试

已确认：超时、取消、重试确认、防重复、幂等、限流、费用和日志留存均由服务端配置管理；每次实际发送前需要用户确认，调用锁定确认时的需求版本，失败记录可按配置允许重试且不得重复创建。

### DEC-Q011 日志治理

更名、归档、启用、删除是否必须记录？日志字段、留存周期、删除和导出规则是什么？

### DEC-Q012 页面交互

详情采用页面还是抽屉？列表搜索字段、排序字段、表单顺序和未保存退出行为是什么？

## 决策更新规则

- 用户确认新规则后，先更新本文件和 PRD，再实现受影响行为。
- 新决定必须注明日期、关联 PRD 编号和影响范围。
- 未确认问题不得通过代码默认值、数据库默认值或前端交互偷偷决定。
