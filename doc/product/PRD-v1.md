# 项目、需求、任务与 Agent 辅助拆分：第一期 PRD

版本：v0.3（开发依据）
日期：2026-10-02
状态：已确认需求可进入开发规划；待确认决定不得作为默认需求实现。

## 1. 文档目的与状态标记

本文档定义第一期项目管理系统的业务范围、已确认规则、验收条件和未决事项。

状态标记：

- **[已确认]**：用户已经确认，可以进入开发规划和验收。
- **[待确认]**：仍需要产品决定，不得由开发或 Agent 自行补全。
- **[第一期不做]**：明确排除在第一期之外。
- **[代码事实]**：只说明当前代码，不代表目标业务已经实现。

## 2. 目标与范围

### 2.1 产品目标

在多个并行项目中记录项目、需求、任务及其变化，支持需求拆分、任务管理和历史追溯。Agent 只能辅助生成任务草稿，正式任务必须经过人工审阅、编辑和保存。

### 2.2 第一期范围

**[已确认]** 第一期包含：基础账号与用户查找、全局角色/菜单/按钮权限、全局字典、项目与成员、项目业务角色绑定、需求及需求版本、任务及任务版本、项目操作日志、Agent 辅助拆分任务、项目级数据隔离、受控项目附件访问、最小列表/详情/搜索/分页交互。

### 2.3 第一期明确不做

**[第一期不做]** 测试功能点思维导图、测试用例执行、Bug 管理、Bug 修复和复验流程、对接现有业务系统、任务附件上传和维护、需求文件导入、Agent 自动保存正式任务、Agent 自动分配任务负责人、自动按需求变更覆盖任务内容/状态/历史依据、项目永久删除、状态流转顺序限制。

## 3. 当前代码事实与边界

### 3.1 代码事实

**[代码事实]** 当前后端是若依基础代码，配置版本为 `3.9.2`。已有用户注册/登录/验证码、系统用户、全局角色、菜单和按钮权限标识、系统字典、系统配置、全局操作日志、通用文件上传和资源访问、Redis/MySQL/JWT 基础能力。

**[代码事实]** 当前工作区已包含 PM-0002 的项目和项目成员实体、创建/列表/详情接口、项目列表与详情页面，以及对应版本化增量 SQL；本机 MySQL 不可用，数据库尚未应用该脚本。需求、任务、项目级操作日志、Agent 拆分任务和项目附件访问控制仍未实现。

### 3.2 现有能力不能直接视为业务要求

**[已确认边界]** 若依用户与全局角色不等于项目内角色；部门数据权限不等于项目成员隔离；超级管理员通配权限不能绕过项目业务边界；匿名可读的 `/profile/**` 不能直接承载私有项目附件；全局操作日志不能直接承载项目正文、附件解析内容和完整 AI 输入输出；数据库中自助注册初始配置为关闭，但产品目标为默认开启并保留配置关闭能力。

## 4. 账号与用户查找

### ACC-01 自助注册

**[已确认]** 任何能够访问系统的人都可以注册账号。

### ACC-02 注册方式

**[已确认]** 注册沿用若依现有流程，不重新设计注册字段，不增加邮箱验证。

### ACC-03 注册后的项目权限

**[已确认]** 创建自己的项目必须具备全局 `project:create` 权限；注册完成后不会因此自动获得其他项目访问权。

### ACC-04 用户查找

**[已确认]** 项目管理员添加成员时可以搜索已注册用户，结果至少显示用户名、昵称和邮箱。邮箱为空时不因本需求改造注册流程；邮箱不是已验证身份凭据。

### ACC-05 注册默认配置

**[已确认]** 产品默认开启自助注册，但保留通过配置关闭注册能力的机制。

### 账号验收条件

- 默认配置下，未登录用户可以完成注册。
- 关闭注册配置后，注册请求被拒绝并返回注册未开启提示。
- 新注册用户不能直接访问其他用户的项目。
- 用户搜索结果只能包含已注册用户，并可显示用户名、昵称和邮箱。
- 邮箱为空时仍可展示用户；注册不要求邮箱验证。

### 账号待确认项

**[待确认]** 用户名、昵称和邮箱的匹配方式、结果数量、分页和多字段组合搜索方式。

## 5. 角色与权限

### AUTH-01 全局角色配置

**[已确认]** 产品、项目经理、运营、开发、测试等业务角色通过全局角色配置维护。创建、编辑、状态修改、日志查看等能力通过权限配置授权，不将岗位名称硬编码为业务判断。

### AUTH-02 全局权限维护

**[已确认]** 超级管理员维护全局角色、菜单权限、按钮权限标识以及角色与权限关系。新增权限标识只代表已经实现的操作，不自动生成业务功能。

### AUTH-03 权限修改即时生效

**[已确认]** 全局角色权限修改后，使用该角色的项目成员在所有项目中的权限按最新配置生效。

### AUTH-04 项目内角色差异

**[已确认]** 同一用户可以在不同项目中绑定不同业务角色；同一用户在同一项目中只能绑定一个业务角色。

### AUTH-05 新成员角色

**[已确认]** 新加入项目的成员必须分配业务角色，加入后立即获得该角色权限，不设置额外的默认只读阶段。

### AUTH-06 创建者资格

**[已确认]** 项目创建者可以不分配业务角色，只持有项目管理员资格。其他后来获得项目管理员资格的成员仍必须同时拥有一个业务角色。

### AUTH-07 项目成员隔离

**[已确认]** 项目成员资格和角色权限共同约束项目访问。未加入项目的用户不能查看或修改项目业务数据；非成员访问项目详情统一返回与不存在项目相同的 HTTP 404。超级管理员仅因全局身份不能自动读取或修改项目业务数据。

### AUTH-08 独立操作权限

**[已确认]** 创建、编辑、需求、任务、需求状态修改、任务状态修改分别配置权限。

### AUTH-09 Agent 权限

**[已确认]** Agent 拆分权限独立配置。拥有该权限的用户同时具备当前项目创建任务和编辑当前项目全部任务的能力。具体采用权限联动还是配置校验属于实现方案，不改变产品结果。

### AUTH-10 项目日志权限

**[已确认]** 查看项目操作日志需要单独授权，并且必须同时满足项目成员资格限制。

### AUTH-11 项目业务角色来源

**[已确认]** 项目成员的业务角色直接引用若依全局角色。项目成员关系保存用户与全局角色的绑定关系，项目内权限使用该全局角色的菜单和按钮权限配置。

### 权限验收条件

- 同一用户在两个项目绑定不同全局角色时，两个项目权限按各自角色生效。
- 修改全局角色权限后，该角色在所有项目中的成员按最新权限生效。
- 未加入项目的用户访问项目、需求、任务、版本、附件或项目日志时均被拒绝。
- 超级管理员没有项目成员资格时，不能仅凭超级管理员身份读取项目业务数据。
- 新成员必须具备业务角色后才能完成加入；创建者可以没有业务角色但具备项目管理员资格。
- 同一成员在同一项目不能同时绑定两个业务角色。
- 没有日志权限的项目成员不能查看项目操作日志。
- 拥有 Agent 权限的用户可以创建任务并编辑当前项目全部任务；无该权限者不能调用 Agent。

### 权限待确认项

**[待确认]** 普通“编辑”权限是编辑自己创建的记录、负责的记录还是全部同类记录；不同全局角色的菜单和按钮映射；项目管理员资格是否拆分为独立按钮权限；超级管理员是否可以查看不含业务正文的项目元数据。

## 6. 全局字典

### DICT-01 字典范围

**[已确认]** 任务分类、需求状态、任务状态由超级管理员全局配置。

### DICT-02 任务分类

**[已确认]** 任务分类支持多选，创建任务时至少选择一项有效分类。

### DICT-03 初始状态选择

**[已确认]** 新建需求和任务时由创建者从有效状态列表选择初始状态，不使用系统默认状态。

### DICT-04 状态流转

**[已确认]** 第一期不限制状态流转顺序；具有对应状态修改权限的用户可以选择任意有效状态。

### DICT-05 历史字典值

**[已确认]** 已被历史记录引用的字典值在历史版本和历史记录中保留原显示值；创建和编辑时使用当前有效字典值。

### 字典验收条件

- 超级管理员可以维护三类字典。
- 创建任务未选择分类，保存失败；创建需求或任务未选择状态，保存失败。
- 创建页面不会自动替用户选择状态。
- 有状态修改权限的用户可以选择任意当前有效状态，无权限者不能修改状态。
- 字典值改名后旧版本仍显示旧名称，新建或编辑记录使用新名称。
- 已停用字典值不能用于新建记录。

### 字典待确认项

**[待确认]** 初始分类、需求状态和任务状态清单；字典值停用或改名后的存量记录编辑行为；是否允许删除字典值，或仅允许停用。

## 7. 项目与成员

### PROJ-01 项目创建

**[已确认]** 已登录用户必须具备全局 `project:create` 权限才能创建项目。创建项目时只有项目名称必填，创建者和创建时间由系统记录。

### PROJ-02 创建者身份

**[已确认]** 项目创建者自动成为首位项目管理员。

### PROJ-03 项目管理员权限

**[已确认]** 项目管理员可以修改项目名称、添加/移除成员、调整成员角色、授予/撤销管理员资格、归档及重新启用项目。

### PROJ-04 管理员最低人数

**[已确认]** 其他管理员可以撤销创建者管理员资格或移出创建者，但项目必须始终至少保留一名管理员。

### PROJ-05 成员加入

**[已确认]** 添加成员后立即生效，不需要成员接受邀请。

### PROJ-06 负责人约束

**[已确认]** 需求和任务负责人只能从当前项目成员中选择。只要成员仍为任一需求或任务负责人，就不能移出项目，必须先调整负责人。

### PROJ-07 项目归档

**[已确认]** 第一期不永久删除项目，采用归档。归档后不能开展新的业务操作，但原成员仍按权限查看相关历史内容。

### PROJ-08 归档项目管理

**[已确认]** 归档后仍允许成员及项目角色管理；管理员可以重新启用项目，恢复正常业务操作。

### PROJ-09 项目名称唯一

**[已确认]** 所有未被永久删除的项目名称全局唯一，归档项目仍占用名称。比较名称前去除首尾空格，并按不区分大小写判断重复。

### 项目验收条件

- 已登录且具备 `project:create` 权限的用户可以创建项目；名称为空时不能保存。
- 缺少 `project:create` 权限的用户创建失败且不产生项目或成员记录；前端不显示新建项目按钮，后端仍独立校验权限。
- 创建后项目创建者自动成为项目管理员。
- 同名项目创建失败，包括与归档项目同名的情况。
- `Project Alpha`、` Project Alpha ` 和 `project alpha` 被视为同名项目。
- 非项目成员访问项目详情返回与不存在项目相同的 HTTP 404，包括超级管理员没有项目成员关系的情况。
- 添加成员后立即生效。
- 仍是需求或任务负责人的成员不能被移除。
- 项目只有一名管理员时，不能撤销其资格或移除该管理员。
- 归档后创建、编辑、状态修改和任务保存等新业务操作被拒绝。
- 归档后符合权限的原成员仍可查看历史内容，管理员仍可管理成员和项目角色。
- 重新启用项目后正常业务操作恢复。

### 项目待确认项

**[待确认]** 归档后允许保留的具体操作；是否允许归档项目改名；归档确认提示；归档时未结束任务处理。

## 8. 需求

### REQ-01 需求创建

**[已确认]** 需求只能在项目内手工创建。标题和富文本正文必填，可以添加附件；第一期不支持文件导入。

### REQ-02 需求负责人

**[已确认]** 需求负责人支持多选，至少选择一人，且只能从当前项目成员中选择。

### REQ-03 需求初始状态

**[已确认]** 创建者手动选择初始状态；状态修改独立授权；不限制状态流转顺序。

### REQ-04 需求历史版本

**[已确认]** 标题、正文或附件清单变化时保留可查看的历史版本。历史版本至少保留标题、正文、附件清单和可打开的旧附件。

### REQ-05 非内容字段变更

**[已确认]** 仅修改负责人或状态不生成内容新版本，但记录操作日志。

### REQ-06 任务不自动同步

**[已确认]** 需求产生新版本时不自动改变关联任务内容、状态或依据版本，只提示任务依据已有更新。

### REQ-07 需求版本对比

**[已确认]** 需求详情提供版本列表，可选择两个版本对比标题、正文和附件变化。

### REQ-08 需求删除

**[已确认]** 有关联任务的需求不能删除。允许删除的需求采用逻辑删除，界面不提供恢复入口。

### REQ-09 版本生成触发

**[已确认]** 只有标题、正文或附件清单发生实际变化时，保存才生成新内容版本；仅修改负责人、状态或无变化保存均不生成新版本。

### 需求验收条件

- 标题或正文为空时不能保存。
- 负责人为空或不属于项目成员时不能保存。
- 标题、正文或附件清单变化后版本数量增加一条。
- 仅修改负责人或状态后版本数量不增加，但操作日志出现对应记录。
- 无变化保存后版本数量不增加。
- 新旧版本均可查看标题、正文和附件清单；旧版本可以打开旧附件。
- 选择两个版本可以看到标题、正文和附件差异。
- 有任务关联时删除失败；逻辑删除后界面不提供恢复按钮。
- 需求更新后关联任务内容、状态和依据版本不变。
- 非项目成员不能通过需求 ID、版本 ID 或附件地址读取内容。

### 需求待确认项

**[待确认]** 富文本格式；附件数量、大小、扩展名、预览和下载规则；附件清单变化判断方式；逻辑删除后的历史可见性；已删除需求是否继续阻止任务关联；版本对比显示样式。

## 9. 任务

### TASK-01 需求与任务关系

**[已确认]** 需求与任务为一对多关系。每个任务只能属于一个需求，不能脱离需求独立存在。

### TASK-02 任务创建方式

**[已确认]** 支持手工新建，以及 Agent 草稿经人工确认后创建正式任务。

### TASK-03 任务字段

**[已确认]** 标题和任务说明必填；分类至少一项且可多选；负责人至少一人且可多选；初始状态手动选择。

### TASK-04 负责人选择

**[已确认]** 负责人由人从项目成员中选择，Agent 不推荐负责人。

### TASK-05 需求版本依据

**[已确认]** 每个任务记录其依据的需求版本。

### TASK-06 需求更新提示

**[已确认]** 需求更新时任务不自动修改，只提示任务依据的需求版本已有更新。

### TASK-07 任务历史原则

**[已确认]** 任务内容变化时保留新版本；仅状态、负责人等普通字段变化时记录操作日志。

### TASK-08 任务版本与需求关联

**[已确认]** 普通字段修改不自动关联最新需求版本。用户明确执行更新任务新版本操作时，新版本关联最新需求版本；旧任务版本继续关联旧需求版本。

### TASK-09 任务版本对比

**[已确认]** 任务详情提供版本列表和两版本对比能力。第一期任务不包含附件，任务版本不包含任务附件快照。

### TASK-10 任务删除

**[已确认]** 任务可以逻辑删除，界面不提供恢复入口。

### TASK-11 第一阶段不支持任务附件

**[第一期不做]** 任务不支持上传附件、维护附件清单、附件版本或附件下载。任务只能记录其依据的需求版本。

### 任务验收条件

- 创建任务必须关联一个需求，不能保存独立任务。
- 标题、说明、分类、负责人或初始状态缺失时保存失败。
- 分类至少选择一项，负责人必须来自当前项目成员。
- Agent 草稿不自动写入正式任务；用户确认后合格草稿才生成正式任务。
- 每个任务版本可以查看其依据的需求版本。
- 需求更新后任务内容和状态不自动改变。
- 普通字段修改不会改变任务依据版本；明确执行更新后新版本关联最新需求版本。
- 任务状态修改不生成内容版本，但记录操作日志。
- 任务详情可以查看版本列表并进行两版本对比。
- 页面和接口均不提供任务附件能力。
- 任务逻辑删除后界面不提供恢复入口。

### 任务待确认项

**[待确认]** 任务逻辑删除后是否仍被需求引用判断；删除任务是否仍出现在历史和日志；已删除任务负责人是否继续阻止成员移除；更新任务新版本的入口、确认方式和字段；任务列表搜索和排序字段。

## 10. Agent 辅助拆分任务

### AI-01 Agent 能力

**[已确认]** 第一期包含 Agent 辅助拆分任务能力。Agent 作为独立可复用能力设计，是否独立部署待确认。

### AI-02 输入内容

**[已确认范围]** 输入包含需求正文和用户选定的需求附件，目标文件类型包括 PDF、Word、Excel 和图片。具体格式、大小和解析能力待确认。

### AI-03 外部 AI 服务

**[已确认]** 允许将需求内容和附件发送至外部 AI 服务。

### AI-04 发送确认

**[已确认]** 每次发送前显示拟发送的需求内容和附件清单，用户确认后才发送。附件默认全选，允许取消。

### AI-05 草稿任务

**[已确认]** Agent 输出可编辑任务列表，不能自动保存正式任务。用户可取消单条、修改内容和分类、手动选择负责人后批量保存。

### AI-06 分类与负责人

**[已确认]** 每条草稿包含建议分类，用户可以调整；任务负责人不由 Agent 生成。

### AI-07 批量保存

**[已确认]** 批量保存时合格条目保存，不合格条目提示失败；失败条目不阻止其他合格条目保存。

### AI-08 调用留痕

**[已确认]** 调用记录包含发起人、项目、需求及版本、时间、所选附件和调用结果，并保存实际发送正文、附件解析内容和返回的任务草稿。原始附件使用已有需求版本记录，不重复复制到日志。

### AI-09 调用记录隔离

**[已确认]** 完整调用记录受项目隔离和单独日志查看权限控制，不能放入允许全局访问的普通日志内容。

### AI-10 调用失败与重试

**[已确认范围]** 调用失败保留失败记录及原因，可以基于同份输入重试；重试具体行为待确认。

### Agent 验收条件

- 未完成发送确认前，外部 AI 服务不会收到请求。
- 发送确认页面显示需求正文和附件清单；取消选择的附件不会发送。
- Agent 结果以可编辑草稿展示，不直接创建正式任务。
- 用户可以删除单条草稿、修改内容和分类。
- 任务负责人必须由用户手动选择。
- 批量保存时合格任务成功保存，不合格任务显示失败原因。
- 每次调用可查询发起人、项目、需求版本、附件、输入、输出和结果。
- 无项目日志权限者不能查看完整 AI 输入和输出。
- 失败调用可查看失败原因。

### Agent 待确认项

**[待确认]** 服务商、模型、密钥管理、数据外发策略、文件扩展名和大小、扫描件/OCR、Excel 多工作表、超时、取消、重试确认、防重复、费用限制、日志留存清理，以及调用期间需求发生变化时使用哪个版本。

## 11. 操作日志与历史

### LOG-01 关键操作留痕

**[已确认]** 第一期关键操作须留痕，至少覆盖项目成员和授权变动、需求与任务的创建/编辑/状态变更以及 Agent 调用。

### LOG-02 项目日志权限

**[已确认]** 项目日志单独授权并按项目隔离；超级管理员不因全局身份自动可见。

### LOG-03 历史与日志职责

**[已确认]** 历史版本用于查看过去的内容和依据；状态、负责人等非版本字段变动使用操作日志。

### LOG-04 AI 记录隔离

**[已确认]** AI 完整输入和输出由项目范围内调用记录承载，不因全局日志查询而泄露。

### 日志验收条件

- 关键操作完成后可查询日志。
- 日志至少能识别操作者、项目、操作类型和操作时间。
- 无项目成员资格者不能查询项目日志；无日志权限的项目成员不能查看日志详情。
- 内容历史与普通操作日志可以分别访问。
- AI 输入输出不出现在无项目权限用户可查询的全局日志中。
- 日志不包含不必要的密码、令牌或认证信息。

### 日志待确认项

**[待确认]** 更名、归档/启用、删除是否必须记录；具体日志字段；保留周期；是否可删除；全局系统日志查看者；AI 调用记录是否可导出。

## 12. 第一期交互基线

### UX-01 最小导航与列表能力

**[已确认]** 第一期采用项目列表、项目详情、项目详情进入需求/任务列表、项目/需求/任务关键词搜索、基础分页、需求/任务版本列表和项目日志入口。

详情可以采用独立页面或抽屉实现，但必须能进入版本对比和日志入口。

### 交互验收条件

- 登录用户可以进入项目列表，且只能看到有权限访问的项目。
- 项目、需求和任务列表支持关键词搜索及分页。
- 从项目详情可以进入需求和任务列表。
- 需求和任务详情可以进入版本列表。
- 权限不足时不能进入项目日志或版本内容。
- 页面不会提供指向无权限项目数据的可直接访问入口。

### 交互待确认项

**[待确认]** 搜索字段、排序字段、详情页面或抽屉、表单字段顺序、未保存退出确认、富文本编辑器样式、附件上传/预览/下载交互。

## 13. 冲突、含糊和代码差异

### 13.1 已解决的冲突或含糊

| 事项 | 原有冲突或含糊 | 本版结论 |
| --- | --- | --- |
| 注册默认值 | 产品要求开放注册，但当前数据库初始配置为关闭 | 产品默认开启，部署仍可配置关闭 |
| 项目业务角色 | 未明确项目角色与若依全局角色的关系 | 直接引用全局角色 |
| 项目名称 | 未明确是否唯一 | 全局唯一，归档项目仍占用名称 |
| 版本触发 | “每次保存版本”与“内容变化才版本”表述冲突 | 只有标题、正文或附件清单实际变化才生成版本 |
| 任务附件 | 未明确任务是否拥有独立附件 | 第一期不做任务附件 |
| 任务与需求版本 | 未明确普通任务编辑是否跟随最新需求 | 普通编辑不跟随；明确更新任务新版本时关联最新需求版本 |
| 前端入口 | 列表、详情、搜索和分页范围未锁定 | 采用项目列表、项目详情、需求/任务入口、关键词搜索和基础分页 |
| 项目创建权限 | PROJ-01 和 ACC-03 原文未说明创建权限要求 | 创建操作必须具备全局 `project:create` 权限；角色授权映射仍按待确认项处理 |
| 项目名称规范化 | 未明确空格和大小写比较方式 | 去除首尾空格后按不区分大小写判断名称重复 |
| 非成员详情响应 | 未明确区分无权和不存在项目的响应 | 非成员访问详情统一返回 HTTP 404 |

- 逻辑删除后历史、日志、负责人占用和关联阻断规则。
- 富文本、附件、版本对比和详细页面交互。
- 字典初始值及改名、停用后的存量记录行为。
- Agent 服务商、模型、文件解析、重试、防重复、费用和数据外发规则。
- 日志字段、保留、删除和导出规则。

### 13.3 代码事实差异

- 当前仓库基于若依 `3.9.2`，并已包含 PM-0002 项目创建、项目成员关系、项目列表/详情隔离的代码和增量脚本；本机 MySQL 不可用，脚本尚未在本机数据库执行。

- 当前全局操作日志不能视为满足项目级日志和 AI 调用记录要求。

## 14. 已确认、待确认和第一期不做总表

### 14.1 已确认需求

自助注册默认开启但可配置关闭；创建项目要求全局 `project:create` 权限；注册不会因此自动获得其他项目访问权；项目成员直接绑定全局角色；项目隔离优先于超级管理员通配权限；项目名称去除首尾空格后按不区分大小写全局唯一且归档项目仍占用名称；非成员访问项目详情返回 HTTP 404；创建者自动成为管理员且项目至少保留一名管理员；负责人必须是项目成员；需求和任务内容版本只在内容实际变化时生成；负责人和状态变化只记日志；需求更新不自动覆盖任务；任务必须归属需求且第一期不支持附件；Agent 只能生成草稿、负责人由人选择、外部调用前必须确认；项目日志、历史版本和 AI 调用记录遵守项目访问边界；第一期具备项目/需求/任务最小列表、详情、关键词搜索和分页。
