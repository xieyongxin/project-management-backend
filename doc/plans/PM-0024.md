# PM-0024：提示任务依据的需求已有新版本

状态：验收通过

## 1. 唯一业务行为

需求产生新的内容版本后，关联任务仍保持原有内容、状态、负责人和依据版本；任务查询结果计算其依据版本是否已不是需求当前版本，并在任务列表显示提示。

## 2. 关联 PRD

- `TASK-06`：需求更新时任务不自动修改，只提示任务依据的需求版本已有更新。
- `TASK-07`：普通字段查询不改变任务内容版本。
- `AUTH-07`：任务列表仍按项目成员关系隔离。

## 3. 范围

- 任务查询模型增加只读 `requirementVersionOutdated` 标记。
- 任务 SQL 将任务版本依据与所属需求当前版本比较。
- 前端任务列表在依据需求列显示“需求有新版本”提示。
- Mapper 测试覆盖当前版本一致和需求版本更新两种结果。

不包含：需求编辑入口、任务内容编辑、任务版本生成、任务自动同步、任务详情交互、搜索排序、删除、附件和 Agent。

## 4. 验收记录

- 后端：`mvn -B -ntp -pl ruoyi-system,ruoyi-admin -am test`，system 59 项、admin 50 项全部通过。
- 前端：`npm run build:prod`，生产构建通过。
- Mapper 场景：任务依据需求当前版本时标记为 `0`；需求当前版本切换到新版本后标记为 `1`；项目成员隔离测试保持通过。
- 真实 HTTP：重启本地后端后，临时需求/任务数据通过任务列表接口读取，需求当前版本改变后返回 `requirementVersionOutdated=1`；临时数据随后清理。

未验证内容：详情页、搜索和排序交互不属于本轮范围。
