# PM-0002 最终核对版：项目创建与项目访问隔离

状态：开发中

本计划记录依据：用户已确认创建项目必须拥有全局 `project:create` 权限。该决定已同步至 PRD-v1.md 的 ACC-03、PROJ-01 和 DECISIONS.md 的 DEC-013；具体角色授权映射仍待确认，本任务不默认分配。

## 1. 唯一业务行为

PM-0002 只规划以下业务范围：

- 创建项目。
- 创建操作仅允许已登录且具备全局 `project:create` 权限的用户执行。
- 建立创建者与项目的成员关系，并标记创建者为项目管理员。
- 查询当前用户所属项目列表。
- 查询项目详情，并按项目成员关系执行访问隔离。
- 非项目成员无法通过项目 ID 读取项目。
- 超级管理员没有成员关系时，不能绕过项目业务边界。

明确排除：

- 成员邀请、成员搜索、成员加入确认。
- 成员移除、角色调整、管理员资格调整。
- 需求、任务、字典、附件、日志、Agent。
- 项目归档、重新启用、项目改名和项目删除。
- 无关配置、依赖升级和重构。

## 2. PRD 对应条目

- `PROJ-01`：创建项目需具备全局 `project:create` 权限，项目名称必填。
- `PROJ-02`：创建者自动成为首位项目管理员。
- `PROJ-09`：项目名称全局唯一。
- `AUTH-07`：项目成员关系约束项目访问，超级管理员不能绕过项目边界。
- `UX-01`：项目列表、项目详情和基础分页入口。
- `ACC-03`：用户创建自己的项目后，不自动获得其他项目访问权。

以下决定沿用上一轮已确认结论：

- 名称去除首尾空格后按不区分大小写判断重复。
- 非成员访问项目详情统一返回 404。

已确认的创建权限规则：

- 创建项目必须具备全局 `project:create` 权限。
- 后端创建接口必须校验该权限；仅登录不等于具备创建权限。
- 前端新建按钮按 `project:create` 权限控制显隐，但该显隐不能替代后端校验。
- 数据库增量脚本登记 `project:create` 按钮权限，不自动将其分配给任何全局角色。具体角色授权映射仍未确认，不属于本轮默认实现。
- 此决定只涉及创建操作；不据此要求项目列表、详情接口或项目路由使用 `project:create` 权限。列表和详情仍分别按登录身份与项目成员关系隔离。

## 3. 数据关系

### `pm_project`

本轮只保留创建、列表和详情所需字段：

- `project_id`：主键。
- `project_name`：去除首尾空格后的展示名称。
- `project_name_key`：规范化名称键，用于不区分大小写的全局唯一约束。
- `creator_id`：创建者用户 ID。
- `create_time`、`update_time`。

本轮不新增：

- `del_flag`。PM-0002 不实现项目删除，也没有逻辑删除验收场景，新增该字段没有本轮用途。
- `status`。PM-0002 不实现归档和重新启用，状态字段在归档功能任务中单独设计和迁移。
- 项目名称修改字段或流程。

### `pm_project_member`

本轮只保留创建者成员关系所需字段：

- `project_id`。
- `user_id`。
- `is_project_admin`。
- `create_time`、`update_time`。

约束：

- `project_id + user_id` 唯一。
- 创建者成员记录的 `is_project_admin=1`。
- 不把 `sys_user_role` 作为项目成员关系。
- 本轮不新增成员业务角色绑定；后续角色绑定另行规划。
- 不使用部门数据范围代替项目成员关系。
- 按当前仓库 SQL 习惯不新增物理外键，使用服务层校验和唯一索引维护关系。

项目记录和创建者成员记录必须在同一个事务中提交。任一写入失败，全部回滚。

## 4. 后端接口及调用路径

### 创建项目

`POST /project`

请求只接受：

```json
{
  "projectName": "项目名称"
}
```

调用路径：

```text
ProjectController
  -> ProjectService.createProject
      -> 获取当前登录用户 ID
      -> 去除首尾空格
      -> 校验名称非空
      -> 生成 projectNameKey
      -> 插入 pm_project
      -> 插入 pm_project_member(is_project_admin=1)
      -> 事务提交
```

创建接口在现有认证基础上还必须校验 `project:create` 全局权限。项目数据访问仍须单独通过成员关系校验；全局权限不能绕过项目隔离。

### 项目列表

`GET /project/list`

参数沿用若依分页参数：

- `pageNum`
- `pageSize`
- 可选项目名称关键词

查询必须由服务端使用当前 JWT 用户 ID 过滤：

```text
ProjectController.list
  -> startPage()
  -> ProjectService.selectProjectsForUser(currentUserId, query)
  -> Mapper 通过 pm_project_member 过滤
  -> getDataTable(list)
```

不能接受前端传入的任意用户 ID 作为过滤依据。

### 项目详情

`GET /project/{projectId}`

调用路径：

```text
ProjectController.getInfo
  -> ProjectService.getProjectForUser(projectId, currentUserId)
  -> 查询项目且要求存在对应成员关系
  -> 项目不存在或当前用户不是成员时返回 404
```

查询中不得因 `SecurityUtils.isAdmin()`、`SUPER_ADMIN` 或全局权限而跳过成员关系。

### 可复用若依约定

- 当前用户：`SecurityUtils.getUserId()`、`BaseController.getUserId()`。
- 分页：`startPage()`、`getDataTable()`、`PageUtils`。
- 响应：`TableDataInfo`、`AjaxResult`。
- 参数校验：`@Validated` 和现有 Bean Validation。
- 异常：`ServiceException` 和现有 `GlobalExceptionHandler`。
- 持久化：现有 MyBatis Mapper、XML、Service、Controller 分层。
- 认证：现有 JWT 和 Spring Security 认证链。

## 6. 项目隔离和超级管理员防护

### 列表隔离

只查询存在以下成员关系的项目：

```text
pm_project_member.project_id = pm_project.project_id
pm_project_member.user_id = 当前登录用户 ID
```

列表响应不暴露其他用户所属项目。

### 详情隔离

项目 ID 查询必须同时满足：

- 项目记录存在；
- 当前用户在项目成员表中存在。

任一条件不满足都返回 404，项目不存在和无权限不可区分。

### 超级管理员

- 超级管理员没有项目成员关系时，列表中不显示项目。
- 超级管理员直接访问非成员项目 ID 时返回 404。
- 不使用若依全局角色、部门数据权限或 `isAdmin()` 绕过项目业务边界。

### 创建一致性

- 项目和创建者成员关系使用同一个事务。
- 成员关系写入失败时项目写入回滚。
- 创建请求不得提交或覆盖 `creatorId`、`userId`、`isProjectAdmin` 等服务端决定字段。

## 7. 验收场景

### 正常流程

- 已登录且具备 `project:create` 权限的用户提交合法项目名称，创建成功。
- 当前用户缺少 `project:create` 权限时，创建请求被拒绝且不产生项目或成员记录；拥有该权限的已登录用户可以继续执行创建。
- 前端对缺少 `project:create` 权限的用户隐藏新建项目按钮；后端权限校验仍独立生效。
- 数据库产生一条项目记录和一条创建者成员记录。
- 创建者成员记录的 `is_project_admin=1`。
- 创建者项目列表能看到该项目。
- 创建者可通过项目 ID 查看详情。

### 参数错误

- 未登录访问接口，沿用现有认证失败行为。
- 项目名称为空或只有首尾空格，创建失败且不产生任何项目或成员记录。
- 项目 ID 不存在、格式非法或为空，详情返回 404。
- 客户端伪造创建者、管理员或成员字段时，服务端忽略这些字段。

### 名称唯一约束

- 首次创建规范化名称成功。
- 再次创建相同规范化名称失败。
- `"项目 Alpha"`、`" 项目 Alpha "`、`"项目 alpha"` 被视为同一名称。
- 重复创建失败时，数据库中仍只有一条项目记录和一条对应成员记录。
- 并发创建同一规范化名称时，由数据库唯一索引保证最多成功一条。

本轮不宣称“重复提交请求具备幂等性”，也不设计幂等请求号。重复请求的可验证结果是：后续请求因唯一约束失败，不会新增第二条相同名称项目。

### 非成员访问

- 用户 B 的项目列表不包含用户 A 的项目。
- 用户 B 访问用户 A 的项目 ID，返回 404。
- 超级管理员没有成员关系时访问该项目 ID，返回 404。
- 非成员访问不存在项目 ID，也返回 404。
- 修改分页、搜索词或伪造用户 ID 不能绕过隔离。

### 一致性验证

- 模拟创建者成员写入失败，项目写入必须回滚。
- 唯一索引冲突不产生孤立项目或孤立成员。
- 既有登录、全局角色、部门数据权限和系统管理功能不受影响。

## 9. 数据库增量脚本

当前仓库已有 SQL 文件位于：

```text
project-management-backend/sql/
```

现有文件使用小写、下划线和 `.sql` 后缀，例如：

```text
sql/ry_20260417.sql
sql/quartz.sql
```

本轮新增脚本放在同一目录，不创建新的 migration 子目录，建议命名：

```text
sql/pm_0002_project.sql
```

脚本只负责：

- 创建 `pm_project`。
- 创建 `pm_project_member`。
- 添加 `project_name_key` 唯一索引。
- 添加 `project_id + user_id` 唯一索引。
- 添加列表和详情查询索引。
- 登记若依 `project:create` 按钮权限，不写入任何全局角色授权关系。

脚本不得：

- `DROP` 现有业务表。
- 清空或重新初始化现有数据库。
- 修改 `sys_user`、`sys_role` 或部门表。
- 写入默认角色、成员、字典或测试数据。
- 添加本轮不需要的 `del_flag`、归档状态或删除流程。
