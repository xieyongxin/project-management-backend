# PM-0029：项目成员逻辑删除需求

状态：验收通过

## 唯一业务行为

项目成员拥有独立 `project:requirement:delete` 权限时，可以逻辑删除没有未删除任务关联的需求。删除后的需求主体、需求内容版本和项目操作日志仍对项目成员可见，并标记为已删除。

## 关联依据

- PRD：`AUTH-07`、`AUTH-08`、`REQ-08`、`TASK-01`、`PROJ-06`、`LOG-01`、`LOG-03`
- 已确认决定：`DEC-014`、`DEC-015`

## 范围

- 后端需求逻辑删除服务和 `DELETE /project/{projectId}/requirements/{requirementId}` 接口。
- 项目成员、归档项目、未删除任务引用和已删除任务引用校验。
- 删除与 `REQUIREMENT_DELETE` 日志的事务一致性。
- 需求列表、详情、版本列表和版本视图保留已删除记录并返回 `isDeleted`。
- 已删除需求禁止内容修改、状态修改和新任务关联。
- 前端删除权限、确认框、错误提示和已删除标记。
- 增量 SQL 仅登记 `project:requirement:delete` 权限。

## 不包含

- 任务逻辑删除接口和任务删除页面。
- 需求恢复入口、需求负责人编辑和需求附件策略。
- 任务编辑、任务版本更新和其他待确认页面交互。

## 验收条件

- 项目成员和独立删除权限均满足时，需求可以逻辑删除。
- 关联任一未删除任务时返回 400；关联任务全部已删除时允许删除。
- 非项目成员返回 404；归档项目返回 400。
- 删除成功后 `pm_requirement.is_deleted=1`，且删除日志类型为 `REQUIREMENT_DELETE`。
- 日志写入失败时删除状态回滚，不能留下半完成删除。
- 删除后的需求、版本和日志仍对项目成员可见；需求和版本视图返回 `isDeleted=1`。
- 已删除需求的内容/状态修改和任务新建关联均返回 400。
- 前端未删除需求显示删除入口，已删除需求隐藏编辑和删除入口并显示状态标记。
