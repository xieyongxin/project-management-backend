# 第一期任务记录

本文件只记录开发任务的执行状态和依据，不擅自确定产品字段、接口、权限或数据库实现细节。

## 任务记录格式

```text
任务编号：PM-XXXX
关联 PRD：ACC-xx / AUTH-xx / ...
行为目标：一句话描述本轮唯一业务行为
范围：本轮允许修改的前后端区域
不包含：明确排除的相邻功能
验收条件：可观察、可复现的结果
状态：待开始 / 开发中 / 待验证 / 已完成 / 阻塞
后端提交：未提交或 commit hash
前端提交：未提交或 commit hash
验证记录：执行的命令、场景和结果
阻塞与待确认：需要用户决定的事项
```

## 任务约束

- 一个任务只对应一个可独立验收的业务行为。
- 同一行为需要前后端改动时，后端和前端使用相同任务编号分别提交。
- 任务不得把待确认决定写成默认实现。
- 任务完成必须填写验收结果和提交编号。
- 失败验证、跳过验证和未覆盖风险必须明确记录。
- 不得为了完成任务顺便加入无关重构、依赖升级或额外功能。

### PM-0002：项目创建与项目访问隔离

关联 PRD：`PROJ-01`、`PROJ-02`、`PROJ-09`、`AUTH-07`、`UX-01`、`ACC-03`

业务目标：已登录且具有全局 `project:create` 权限的用户创建项目，创建者自动成为项目管理员；项目列表只返回当前用户所属项目；非项目成员不能通过项目 ID 访问项目；超级管理员不能仅凭全局身份绕过项目业务访问边界。

明确包含的范围：

- 项目创建及项目名称必填校验。
- 创建接口要求当前登录用户具有全局 `project:create` 权限；权限不自动分配给任何全局角色。
- 创建者项目成员关系和项目管理员标记。
- 当前用户所属项目列表、关键词查询和基础分页规划。
- 项目详情查询及成员关系访问校验。
- 项目名称去首尾空格后按不区分大小写的数据库唯一约束规划。
- 项目创建和创建者成员关系的事务一致性规划。

明确排除的范围：

- 成员邀请、成员搜索、成员加入确认、成员移除和角色调整。
- 需求、任务、字典、附件、日志和 Agent。
- 项目归档、重新启用、改名、删除和历史恢复。
- 全局角色与 `project:create` 的授权映射；本任务只登记权限，不默认分配。
- 幂等请求机制、无关重构、依赖升级、部署和密钥配置。
- 本轮不新增 `del_flag`、归档状态或数据库初始化数据。

验收条件：

- 合法创建请求成功写入一条项目记录和一条创建者成员记录，成员记录的 `is_project_admin=1`。
- 项目写入或创建者成员写入任一失败时，另一条记录不单独保留。
- 项目名称为空或只有首尾空格时创建失败且不产生项目或成员记录。
- 缺少 `project:create` 权限的用户调用创建接口被拒绝且不产生项目或成员记录；拥有该权限的用户可以创建。
- 缺少 `project:create` 权限时前端不显示新建项目按钮；后端权限校验独立有效。
- 同一规范化名称再次创建时因数据库唯一约束失败，项目记录和成员记录数量不增加；本轮不承诺请求幂等成功。
- 当前用户的项目列表只返回其项目成员关系覆盖的项目。
- 非成员访问其他项目 ID 返回 404，且与不存在项目的响应语义一致。
- 没有成员关系的超级管理员不能通过列表或详情接口读取项目业务数据。
- 伪造用户 ID、调整分页或搜索参数不能绕过项目隔离。

- 创建项目必须具备全局 `project:create` 权限；用户于 2026-10-02 在本对话确认。
